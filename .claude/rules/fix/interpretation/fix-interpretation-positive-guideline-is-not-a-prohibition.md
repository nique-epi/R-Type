# RULE: A positively phrased guideline is not a prohibition — never remove a feature through a contrapositive reading

## Rule

1. **A positive instruction is not reversed.** "Do X in case Y" allows X everywhere; only an explicit negative phrasing ("do not", "never", "avoid") forbids. Before removing something by citing an instruction (Epitech subject, library docs, a teammate's remark), check that it says to remove it — not that it recommends adding it somewhere else.
2. **Read the whole page or section before drawing an exclusion from it**: the deciding sentence is often two paragraphs further down.
3. **Do not write a deduction as if it came from the source**: quote what the source says, separately from what you conclude.

## Example

- ❌ **Before (wrong)**: "the subject requires the server to be authoritative over monster positions" → read as "the client must simulate nothing" → local prediction of the player's ship removed, game unplayable with latency.
- ✅ **After (right)**: server authority over monsters does not forbid predicting the player's ship, corrected by the server; prediction stays.
